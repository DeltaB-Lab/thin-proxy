# thin-proxy

一个部署在 Cloudflare Workers 上的轻量 API 反向代理，使用 D1 保存配置。客户端固定代理地址和转发 Key，在网页中切换上游地址与密钥，无需反复修改客户端。

## 部署

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/DeltaB-Lab/thin-proxy)

点击按钮，在自己的 Cloudflare 账号中选择独立的项目名称，并为新部署新建 D1 数据库。按提示设置 `ADMIN_KEY` 与 `UPSTREAM_KEY_ENCRYPTION_KEY` 两个随机密钥，替换示例值。默认使用 workers.dev 地址；部署命令会先初始化 D1，再发布服务，无需填写原作者的账号或域名。

账号内已有同名数据库时，Cloudflare 可能默认选中它；请在 D1 下拉框选择「+ 新建」，避免多个实例共用配置和密钥数据。首次部署建议关闭「启用预览构建」。

密钥生成方式、手动部署和已有生产环境的独立配置见[部署文档](docs/04-自动部署.md)。

## 怎么用

1. 部署后打开 `https://你的域名/_relay/`，使用 `ADMIN_KEY` 登录。
2. 添加上游 HTTPS 地址、上游 Key 和鉴权方式（Bearer 或 x-api-key），可设为默认上游。
3. 创建转发 Key，选择有序上游列表或跟随默认上游，再填入客户端：

```text
Base URL: https://你的域名
API Key: sk-...（网页创建的转发 Key，含前缀共 64 个字符；已有 relay_ Key 仍可用）
```

客户端需要 `/v1` 时，在 Base URL 后加 `/v1`。拼接处重复的完整 `/v1` 段会自动合并，例如上游 `/gateway/v1` + 请求 `/v1/messages` → `/gateway/v1/messages`；其他路径段、编码和查询参数保持原样。

支持通过 `Authorization: Bearer <转发 Key>` 或 `x-api-key: <转发 Key>` 调用；管理密钥不能用于转发。每个 Key 可独立选择多个上游并调整顺序，通过“启用故障转移”开关控制路由：开启时按顺序选择未冷却项；关闭时仅直连第一项，不读取或记录故障状态。单上游及跟随默认的 Key 始终直连。每次请求只回源一次，失败后由客户端决定是否重试。配置变更默认最多约 30 秒传播到其他实例，已有长连接继续使用原上游。

在 Key 列表点击“编辑”可修改名称、上游顺序和故障转移开关，改名不会改变 Key。新建 Key 默认关闭故障转移，选择至少两个指定上游后才能开启；关闭保留列表和共享故障状态，不影响其他 Key。旧多上游 Key 保持原行为，旧单上游 Key 直接转发。新建 Key 可从列表再次查看或复制，服务端保存摘要和加密副本；旧 Key 若只有摘要则无法恢复明文，仍可正常调用和修改上游。

在 Key 列表点击“停止服务”可暂停某个 Key，保留原 Key、名称及上游配置，之后可点击“恢复服务”重新启用。停止后新的 HTTP、SSE 和 WebSocket 握手请求返回 `403 KEY_DISABLED`，不会回源，也不影响其他 Key。变更按配置缓存 TTL 同步（默认最多约 30 秒），已经建立的连接继续运行。旧 Key 默认保持启用，无需数据库迁移。管理 API 使用 `PATCH /_relay/api/keys/:id`，传入 `{ "enabled": false }` 停止、`{ "enabled": true }` 恢复；列表和快照返回 `enabled` 状态。

## 做什么、不做什么

### Codex 模型目录

每个上游可选填「模型目录 URL」（管理接口字段 `modelCatalogUrl`），用于对话与模型目录地址不同的服务。客户端将 `model_catalog_url` 设置为 `https://你的域名/backend-api/codex/models`，请求才会经过本代理。

- 请求路径精确匹配 `/backend-api/codex/models` 时，先按转发 Key 的配置选出上游；填写了模型目录 URL 就直接请求这个完整地址，不再拼接 Base URL。
- 留空时沿用普通拼接规则：例如上游为 `https://up.example/v1`，目录目标就是 `https://up.example/v1/backend-api/codex/models`。这里使用本次选中的上游，不一定是全局默认上游。
- 保留客户端查询参数及重复值；模型目录 URL 自带同名参数时以配置为准。目标仅支持 HTTPS，禁止凭据、fragment、本机/私有地址及代理自身。
- 复用所选上游的 Key 和鉴权方式；目标服务必须接受这套凭据。返回内容不转换，目标需提供 Codex 可用的模型目录。
- 启用故障转移的 Key 仍跳过冷却或正在探测的上游；目录请求的成功、HTTP 错误、连接失败和超时均不记录或清除对话上游的故障状态，也不占用恢复探测。每次请求只回源一次，全部上游不可用时仍返回 503。
- 管理接口 PATCH 省略该字段会保留原值；空字符串或 `null` 会清空。旧配置无需迁移；修改目录地址不重置对话故障状态。页面「测试鉴权」仍检测 Base URL 下的 `/models`，不验证独立模型目录。

### 通用代理能力

上游编辑页的「测试鉴权」会分别展示 Bearer 和 x-api-key 请求 `/models` 返回的模型 ID，去重并显示数量；列表只供查看，不保存为模型配置，也不代表模型调用权限已验证。

- **支持** HTTP、流式响应、SSE 和 WebSocket；业务请求体、上游响应体和 WebSocket 消息不解析、不改写、不重新序列化。
- **处理** 目标 URL、转发 Key 校验、上游鉴权替换，以及连接相关 headers 和管理 Cookie 清理。管理接口会解析 JSON；代理自身错误会生成 JSON 响应。
- **失败冷却** 仅对已开启故障转移的请求生效。网络错误、等待响应头超时、401 / 403 / 408 / 429 和 5xx 使上游冷却，当前错误直接返回；客户端下次请求跳过冷却项。默认冷却 1800 秒（30 分钟），`UPSTREAM_COOLDOWN_SECONDS` 可设为 1–86400 的整数。到期每个实例只允许一个请求探测，非上述故障响应恢复可用，失败开启下一轮冷却；全部不可用返回 503 和 `Retry-After`。故障状态保存在 D1 上游配置中，其他实例随默认 30 秒缓存刷新同步，重启后重新读取。正常请求不增加 D1 查询，故障上报和手动清除产生少量额外读写。每次回源超时默认 300 秒，`UPSTREAM_TIMEOUT_SECONDS` 可设为大于 0、最多 300 秒。
- **手动恢复** 上游卡片显示故障原因和预计恢复时间，可点击“清除故障状态”允许重新尝试；这不代表已经验证上游恢复。清除推进健康版本，旧请求不能写回故障；同一轮重复故障上报静默忽略，不延长截止时间。D1 故障写入失败保留本机冷却，仅记录内部错误。
- **请求体** 所有请求直接流式传递，不缓存或重放，没有项目自设的 8 MiB 上限；实际大小仍受 Cloudflare 和上游限制。已接受的 HTTP / SSE / WebSocket 连接不会因冷却状态变化而切换。
- **不做** 模型映射、协议转换、负载均衡或自动跟随重定向，客户端与上游需使用兼容协议。
- **不提供** 多用户、计费、用量统计、对话存储或业务内容日志；Cloudflare 平台调用日志另行适用。
- **不自动放宽 CORS**，不支持通过 URL 查询参数传 Key；浏览器原生 WebSocket 无法自定义鉴权头的场景不保证兼容。

透传指应用层内容不改写，不保证底层网络分块、压缩或 WebSocket 帧边界一致。

## 本地运行

需要 Node.js 22.12+。

```sh
npm ci
npm run init:local
npm run db:local
npm run dev
```

打开 `http://localhost:8787/_relay/`，使用生成的 `.env` 中的 `ADMIN_KEY` 登录。请保管好 `.env`，不要提交密钥。
