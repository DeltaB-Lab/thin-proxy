# thin-proxy 设计文档

版本：V1.8（Key 故障转移开关与直连隔离）
日期：2026-10-15
依据：[需求文档](./01-需求文档.md)

## 1. 核心模型

一个部署、一份上游列表、一个全局默认上游、多个仅调用的转发 Key。每个 Key 可指定有序上游列表并设置故障转移开关；开启后按顺序选择未冷却项，关闭则仅直连第一项。单上游或未绑定时（跟随默认）始终直连，不参与健康状态。每次请求仅回源一次。没有用户表、用户归属字段或普通用户角色。

管理网页只接受 Secret 中的 ADMIN_KEY 登录，转发 Key 只能调用代理。D1 保存单行配置快照，Worker 使用默认 30 秒实例内存缓存；网页登录使用无服务端会话表的签名 Cookie。以下接口及具体字段为建议方案。

## 2. 页面与路由

| 路径 | 用途 |
| --- | --- |
| /_relay/ | 登录与管理页面 |
| /_relay/api/* | 管理 API |
| 其他路径 | HTTP / SSE / WebSocket 代理 |

保留 /_relay 及其子路径。客户端 Base URL 为 https://relay.example.com；客户端要求 /v1 时可配置 https://relay.example.com/v1。静态资源 fallback 不能截获业务路径。

登录时输入管理密钥，验证后换取短期签名 Cookie，不把原始密钥放入 URL 或 localStorage。管理页面分为上游区域和转发 Key 区域，不区分用户或角色页面。保存后提示“已保存，其他实例可能约 30 秒后生效”；管理列表直接读取 D1，不使用代理缓存。

上游区域支持新增、编辑、选择、取消选择、删除。编辑时上游 Key 留空代表保持原值，不回显已保存的明文。删除默认上游或被 Key 绑定的上游返回冲突。

Key 区域支持创建、再次查看与复制明文、查看元数据、修改名称及上游绑定、撤销。轮换方式为“创建新 Key → 修改客户端 → 撤销旧 Key”，无需单独重置接口。页面展示每个 Key 的有序上游列表或跟随的默认上游，创建和编辑时可添加、移除、上移、下移。旧 Key 缺少加密副本时注明不可查看明文。

## 3. URL 规则

基础 URL 为 HTTPS 协议、主机和可选固定路径前缀，不接受嵌入凭据、查询参数或 fragment。

```text
目标路径 = 上游路径前缀（去掉末尾分隔斜杠） + 请求路径（移除拼接处重复的一个 /v1 段）
目标查询字符串 = 原始请求查询字符串
```

仅当上游路径前缀以 /v1 结尾、请求路径为 /v1 或以 /v1/ 开头时，移除请求开头的一个 /v1；按完整路径段匹配，区分大小写。其他位置、/v10、/v1beta 和编码路径不改写，不对路径解码再编码，不排序查询参数。每次尝试候选上游时，使用原始请求路径与该上游前缀独立计算。目标主机始终来自保存的上游配置，不能被请求路径覆盖。

| 基础 URL | 请求路径 | 目标 |
| --- | --- | --- |
| https://a.example.com | /v1/messages?x=1 | https://a.example.com/v1/messages?x=1 |
| https://a.example.com/gateway | /v1/messages | https://a.example.com/gateway/v1/messages |
| https://a.example.com/v1 | /messages | https://a.example.com/v1/messages |
| https://a.example.com/v1 | /v1/messages | https://a.example.com/v1/messages |
| https://a.example.com/gateway/v1/ | /v1/messages | https://a.example.com/gateway/v1/messages |
| https://a.example.com/v1 | /v1beta/messages | https://a.example.com/v1/v1beta/messages |

页面提示拼接处重复 /v1 的处理方式。实际序列化受 Workers URL / Fetch API 约束。WebSocket 对外使用 WSS，内部向对应 HTTPS 上游发起 Upgrade，共用同一上游配置及路径拼接规则。

## 4. 鉴权与头处理

入站接受以下二选一：

```http
Authorization: Bearer <转发Key>
```

```http
x-api-key: <转发Key>
```

两者同时存在且值相同可接受，值不同返回 400；格式不合法则拒绝。不从 Cookie、查询参数、请求体或 WebSocket 消息寻找转发凭据。

计算 Key 的 SHA-256 摘要，在未过期配置快照构建的摘要到 Key 记录的 Map 中匹配，不尝试 ADMIN_KEY 回退认证。每个新请求都在内存检查 Key；仅缓存缺失或过期才读 D1。缓存有效时未知 Key 直接拒绝，不因每个未知 Key 强制刷新数据库。新建 Key 因此也可能需要等待其他实例刷新。

验证后移除入站 Authorization 和 x-api-key，按上游配置写入 Authorization: Bearer 或 x-api-key。保留 Content-Type、Accept、版本头、幂等 Key 等业务头；Host 由目标地址决定，普通逐跳头按协议处理。WebSocket Upgrade 使用专用分支，保留升级和子协议协商所需信息。

移除项目专属会话 Cookie，不主动改写其他业务 Cookie、Origin 或客户端 IP。不承诺头顺序、大小写、压缩表示、分块或 WebSocket 帧边界一致。

## 5. 转发流程

1. 分离管理路径与代理路径。
2. 获取未过期的配置快照：内存命中直接使用，缺失或过期则等待共用的 D1 加载；失败返回 503。
3. 在同一快照中校验转发 Key，取得其 upstreamIds 指定的有序上游列表，未绑定则取得全局默认上游；无有效 Key 则拒绝，无上游则返回配置错误。
4. 故障转移关闭、单上游或跟随默认时直接选择目标，忽略本地与 D1 故障状态；仅在故障转移开启且指定两个及以上上游时，按列表顺序选择首个未冷却且未被探测的上游；全部不可用返回 503 UPSTREAMS_COOLING_DOWN 和 Retry-After，不访问上游。
5. 解密该上游 Key、构建 URL、替换鉴权，只回源一次。请求体直接使用原流；GET / HEAD 不附带请求体。
6. 仅故障转移请求的网络错误、等待响应头超时、401 / 403 / 408 / 429 和 5xx 将该上游标记为冷却。直连不创建、续期或清除故障，不占用探测名额，也不提交故障 SQL。当前 HTTP 响应原样返回，包括失败响应体及头；重定向不跟随。仅客户端下一次请求可能选择另一上游。
7. HTTP / SSE 直接返回流；WebSocket 保留升级连接对象返回。

不解析或改写业务载荷，不缓存、复制或重放请求体，没有项目自设的请求体大小上限。实际大小受 Cloudflare 和上游限制。回源等待响应头默认 30 秒（UPSTREAM_TIMEOUT_SECONDS，大于 0 且不超过 300 秒），取得响应头后清除计时器。网络错误返回 502，超时返回 504；客户端取消返回 499，不触发冷却。开始响应后若中断，不重试、不追加错误 JSON，也不据此改变健康状态。

冷却默认 1800 秒（30 分钟，UPSTREAM_COOLDOWN_SECONDS，1–86400 的整数）。请求发出前固定上游健康版本；失败立即更新本机内存，并通过 waitUntil 上报 D1，不等待写入才返回原上游错误。数据库写入失败保留本机冷却，只记录不含凭据的内部错误。

故障上报使用一条原子条件 UPDATE：按上游 ID 在当前 JSON 中定位，要求 healthRevision 等于请求携带版本且 faultUntil 已过期；只修改该上游健康字段，递增 healthRevision 和整体 version，以数据库时间计算截止时间，RETURNING version、config_json。首个上报成功，其余更新 0 行静默结束，不告警、不重试、不使用新版本替旧请求再报。每个实例合并同一轮并发失败，跨实例仍可能提交条件更新，但只有首个匹配者实际修改状态。整体配置版本校验防止管理员用旧 JSON 覆盖故障；上游数组重排不影响按 ID 定位。

内存健康状态随配置缓存刷新按健康版本协调；更高版本替换旧本地冷却，旧快照或旧请求不能回写。普通缓存命中请求不增加 D1 查询；故障提交成功后发布返回快照，其他实例默认约 30 秒内按需刷新，传播时间从成功写入 D1 起计。无主动广播或后台轮询，D1 不可用时无法保证共享状态传播。

冷却到期后，每个实例的首个请求在异步操作前占用探测名额，其他请求继续选择后续上游；非故障状态（包括 400 / 404 / 422）恢复本机优先级，失败按当前健康版本开启新一轮冷却。不做全局唯一探测；取消或本地错误释放名额，不新增冷却。全部不可用时，Retry-After 取最早冷却到期或在途探测预计响应头截止时间，向上取整且至少 1 秒；它是重试建议，不保证届时可用。

手动清除原子设置 faultUntil=0、faultReason=null，并始终递增 healthRevision 和整体 version，包括当前无故障时。清除前发出的请求不能重新写回；清除后新版本请求仍可开启新故障。清除表示允许重试，不表示已验证恢复。URL、鉴权类型或密钥替换同样推进健康版本并清除故障；名称、Key、路由顺序及默认上游变化保留健康状态，删除上游清理本地记录。

客户端自行重试可能重复执行已被上游接受的操作；保留客户端原有幂等头，但不保证不同上游共享幂等状态。配置、解密和循环回源错误立即返回，不当作上游故障。

### 不透明业务流约束

代理路径不能调用 Request/Response 的 json()、text()、formData() 或 arrayBuffer() 来整包读取业务体；不使用 JSON.parse、JSON.stringify、文本编解码或 SSE 解析器转换业务载荷。所有请求体直接使用原请求的流；响应体直接使用上游响应流；WebSocket 直接透传升级连接。不得解包、增加外层对象、调整字段层级、增删或重命名字段，不能因不同模型或接口走不同的业务转换分支。

URL、鉴权头和 Upgrade 信息的读取属于必要的代理控制逻辑；管理 API 的 JSON 校验、D1 配置 JSON 的序列化不受此业务体限制。Worker 不主动改变业务载荷，但运行时的 HTTP 编码、压缩与传输分块不承诺在线路字节层面完全相同。

## 6. 数据结构

采用 D1 的单表单行配置，不建用户表、会话表或请求日志表。

| 表 | 字段 | 说明 |
| --- | --- | --- |
| config | id、version、config_json、updated_at | id 固定为 1 且为主键，version 单调递增，迁移创建空配置 |

config_json 结构：

```ts
type Config = {
  activeUpstreamId: string | null;
  upstreams: Array<{
    id: string;
    name: string;
    baseUrl: string;
    authType: "bearer" | "x-api-key";
    keyCiphertext: string;
    keyIv: string;
    keyVersion: number;
    healthRevision?: number; // 非负整数，缺省 0
    faultUntil?: number; // Unix 毫秒时间，缺省 0
    faultReason?: string | null; // timeout / connection / HTTP 状态码，缺省 null
  }>;
  accessKeys: Array<{
    id: string;
    name: string;
    keyHash: string;
    keyPrefix: string;
    createdAt: string;
    upstreamIds?: string[] | null; // 非空有序列表；null 跟随 activeUpstreamId
    failoverEnabled?: boolean; // 显式开关；旧记录缺省按多上游列表启用
    upstreamId?: string | null; // 仅兼容旧单上游记录
    encryptedKey?: { keyCiphertext: string; keyIv: string; keyVersion: number };
  }>;
};
```

新记录写入 failoverEnabled 布尔开关；管理页面新建默认 false。开启要求 upstreamIds 至少两项；关闭保留列表，仅用第一项。旧记录或旧 API 客户端未传开关时，多上游保持原有故障转移，单上游和默认路由直连。PATCH 可单独修改开关；未传时保留已有显式开关，切换到单上游或默认路由时自动关闭；显式开启但不足两项返回 400。开关变化不改变上游共享健康状态，重新开启后沿用该状态；在途请求按开始时快照执行，新配置按正常缓存周期传播，无需数据库迁移。

新记录只写 upstreamIds：null 表示跟随默认，1–100 个不重复的 ID 表示顺序；空数组、重复 ID、错误类型拒绝。旧 upstreamId 自动视为单元素列表，没有绑定字段则跟随默认，无需表结构迁移。读取快照校验引用，悬空或格式错误使配置读取返回 503。创建可省略 upstreamIds；修改可传 name、upstreamIds、failoverEnabled 中的一项或多项。名称沿用创建时的校验（去首尾空白、不能为空、输入最多 100 字符）；仅改名保留原凭据与路由，仅改路由保留名称，两项一起修改时原子提交。修改路由时必须显式传列表或 null；接受旧客户端 upstreamId 写入并转换成列表，不接受同时传两种字段。

项目维护的 D1 查询必须显式列出所需字段，禁止使用 `SELECT *` 或 `表名.*`。当前配置读取固定为 `SELECT version, config_json FROM config WHERE id = 1`，不读取无用的 id 和 updated_at。

迁移工具同样遵守显式字段约束：锁定 Wrangler 4.151.0，通过 scripts/patch-wrangler.mjs 将其迁移历史查询改为 `SELECT id, name, applied_at FROM "d1_migrations" ORDER BY id`。安装依赖时自动应用，db:local / db:remote 执行前再次校验；版本或目标代码不匹配时停止，不回退到未修补的查询。保留 Wrangler 的迁移历史、排序和事务执行方式；升级依赖时必须复核补丁并运行迁移测试。此前已有的查询历史不会被删除。

以主键读取一行取得完整配置，不按上游或 Key 数量增加读取行数；实际扫描量以 D1 的 meta.rows_read 为准。上游和转发 Key 都存于该行的 config_json，读取时取得整个配置 JSON；显式列名不等于只读取其中某个上游或 Key。version 用于并发修改校验和防止旧加载覆盖新缓存，不为它单独逐请求查询。

常规配置管理写入先从 D1 主实例读取最新版本，校验目标存在、默认上游及被绑定上游不可删除、Key 摘要唯一等约束，再执行 `UPDATE config SET config_json = ?, version = version + 1, updated_at = ? WHERE id = 1 AND version = ?`。影响行数为 0 时返回 409，提示刷新后重试，不覆盖其他并发修改；成功后将本次提交的版本及快照发布到本实例缓存。健康字段兼容旧 JSON，不需要新增表或表结构迁移。

常规配置编辑校验后若配置未变化，直接返回成功，不执行 UPDATE、不递增版本或更新时间，也不延长代理缓存 TTL。Key 的上游列表按顺序比较；旧绑定表示在语义未变化时保留原样。显式提交非空上游密钥仍按密钥替换处理。无变化操作以本次主实例读取为准，真实修改继续使用版本条件更新。手动清除故障不走无变化优化，始终推进健康版本以阻止旧请求写回。

新转发 Key 使用 `sk-` 前缀加 61 个 Base64URL 随机字符（大小写字母、数字、`-`、`_`），总长 64 个字符，保留 366 位安全随机熵。已有 `relay_` 前缀加 43 个 Base64URL 字符的 Key 继续有效，不迁移或重生成。摘要用于调用鉴权；新 Key 还保存 AES-GCM 加密副本，供管理员按需再次查看或复制。key_prefix 仅用于辨识，不用于认证。

网页登录使用固定有效期的签名 Cookie，建议 1 小时，不存数据库。负载仅包含用途、签发时间、到期时间和随机 nonce，不包含管理密钥或上游 Key。通过 HKDF-SHA-256 从当前 ADMIN_KEY 派生专用签名密钥，使用固定用途标识 `worker-relay/admin-session/v1`；用 HMAC-SHA-256 对编码后的负载签名，固定算法并验证签名、用途、时间及最大有效期。使用 Web Crypto 验签，不接受客户端选择算法。管理密钥须足够随机，不能使用短口令。

Cookie 使用 Secure、HttpOnly、SameSite=Strict，Path=/_relay/；不使用要求 Path=/ 的 __Host- 前缀。每次管理请求按当前 Secret 验签，不查询 D1；Secret 轮换生效后旧签名不再有效。退出仅清除浏览器 Cookie，不承诺已复制令牌立即失效；到期或轮换管理密钥可使其失效。

### 配置缓存规则

- 默认 TTL 为 30 秒，可通过非敏感部署变量 `CONFIG_CACHE_TTL_SECONDS` 调整；设为 0 表示每次读取。
- 模块级缓存保存版本、不可变快照、Key 摘要到 Key 记录的 Map 和过期时间，缓存中保留上游 Key 密文，回源前解密。
- TTL 从本次 D1 读取发起时计时，不因每次命中延长；若读取完成时已过期，本次等待请求可使用刚读结果，但不能再把它当成新的有效 30 秒缓存。
- 同一实例使用一个正在加载的 Promise 合并并发读取，完成或失败后清除；不定时轮询，无请求就不刷新。
- 正常刷新从主实例读最新配置，失败返回 503，不延长或使用过期快照。
- 管理提交成功后更新本实例缓存；迟到的旧版本读取不得覆盖新版本，等待旧读取的请求优先使用已发布的新版本。
- 管理并发写入也按版本单调发布；旧版本不能覆盖新版本，也不能通过重复发布旧版本延长 TTL。
- 已取得快照的在途请求可继续完成；其他实例无主动失效通知，缓存过期后按需刷新，不承诺全站每 30 秒只读一次。

## 7. 管理 API 草案

统一前缀 /_relay/api。登录只接受管理密钥，其余只接受有效管理会话。所有修改操作含登录均校验同源 Origin。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | /session | 验证管理密钥，创建会话 |
| DELETE | /session | 清除当前浏览器 Cookie 并退出，无服务端会话撤销 |
| GET | /snapshot | 一次主实例读取返回同版本的 config、脱敏 upstreams 和 keys；管理页初始化及保存后刷新使用此接口 |
| GET | /config | 返回代理地址及当前上游 |
| GET / POST | /upstreams | 列表 / 新增上游 |
| PATCH / DELETE | /upstreams/:id | 编辑 / 删除非当前上游 |
| POST | /upstreams/:id/clear-fault | 管理员同源操作；原子清除故障并推进健康版本，已清除状态仍推进版本 |
| PUT | /active-upstream | 全局选择，null 表示取消 |
| GET / POST | /keys | 元数据列表（含 upstreamIds、failoverEnabled、canReveal）/ 创建并返回明文 |
| PATCH | /keys/:id | 修改 name、upstreamIds 和/或 failoverEnabled；路由为有序 ID 列表或 null（跟随默认） |
| POST | /keys/:id/reveal | 管理会话及同源校验后返回 Key 明文；旧摘要 Key 返回 409 KEY_NOT_RECOVERABLE |
| DELETE | /keys/:id | 撤销转发 Key |

上游查询不返回密文或明文 Key；Key 列表不返回摘要、密文或明文。查看接口使用 POST、Cache-Control: no-store，从 D1 主实例读出后按用途与 ID 解密并核对摘要，不修改配置；已撤销 Key 返回 404。关闭明文弹窗或退出登录即清空 DOM 中的明文。所有管理读写直接访问 D1，常规配置编辑使用整体版本条件更新，清除故障只原子修改目标上游健康字段，保证默认上游和 Key 绑定引用有效且不丢失并发修改，不静默选择其他项。

## 8. 错误与浏览器行为

Worker 自身错误返回 JSON error.code 与 error.message；上游错误保留原状态与内容。

| 状态 | 场景 |
| --- | --- |
| 400 | 参数、URL 或鉴权头冲突 |
| 401 | 管理密钥错误、当前快照中的转发 Key 无效、签名 Cookie 无效或过期 |
| 403 | 管理请求来源校验失败 |
| 404 | 配置或 Key 记录不存在 |
| 409 | 未绑定且无默认上游、删除默认或被绑定上游、配置版本冲突、旧摘要 Key 无法查看 |
| 499 | 客户端取消 |
| 504 | 等待上游响应头超时 |
| 502 | 回源网络错误 |
| 503 | 配置或存储不可用；全部上游冷却或正在探测时附带 Retry-After |
| 500 | 解密失败或内部错误 |

Cloudflare 平台错误可能在 Worker 外产生，不能保证统一结构。

页面与管理 API 同源。代理不自动放宽 CORS、不回答匿名预检，不改写上游 CORS 头，不保证任意跨域网页可调用。第一版不提供浏览器 WebSocket 的查询参数或子协议鉴权方案。

## 管理侧鉴权检测

`POST /_relay/api/test-auth` 需要管理会话及同源请求，接收 baseUrl、可选 id 和 key。复用上游地址校验；只允许对原地址使用已保存的加密密钥。服务端并发发出三个 GET /models 请求（匿名、Bearer、x-api-key），各自 10 秒超时，不跟随重定向；仅检查最多 256 KiB 的模型列表 JSON，不回传密钥或上游响应体。返回两种方式的 HTTP 状态及 available / rejected / unknown，不写 D1、不更新缓存。此管理工具独立于透明转发路径。
