# thin-proxy 设计文档

版本：V1.2 草案（D1 + 实例内存缓存）
日期：2026-10-15
依据：[需求文档](./01-需求文档.md)

## 1. 核心模型

一个部署、一份上游列表、一个全局当前上游、多个仅调用的转发 Key。没有用户表、用户归属字段、普通用户角色或 Key 专属路由。

管理网页只接受 Secret 中的 ADMIN_KEY 登录，转发 Key 只能调用代理。D1 保存单行配置快照，Worker 使用默认 30 秒实例内存缓存；网页登录使用无服务端会话表的签名 Cookie。以下接口及具体字段为建议方案。

## 2. 页面与路由

| 路径 | 用途 |
| --- | --- |
| /_relay/ | 登录与管理页面 |
| /_relay/api/* | 管理 API |
| 其他路径 | HTTP / SSE / WebSocket 代理 |

保留 /_relay 及其子路径。客户端 Base URL 为 https://relay.example.com；客户端要求 /v1 时可配置 https://relay.example.com/v1。静态资源 fallback 不能截获业务路径。

登录时输入管理密钥，验证后换取短期签名 Cookie，不把原始密钥放入 URL 或 localStorage。管理页面分为上游区域和转发 Key 区域，不区分用户或角色页面。保存后提示“已保存，其他实例可能约 30 秒后生效”；管理列表直接读取 D1，不使用代理缓存。

上游区域支持新增、编辑、选择、取消选择、删除。编辑时上游 Key 留空代表保持原值，不回显已保存的明文。删除当前项返回冲突。

Key 区域支持创建、一次性复制明文、查看元数据、撤销。轮换方式为“创建新 Key → 修改客户端 → 撤销旧 Key”，无需单独重置接口。页面明确展示全部 Key 共用当前上游。

## 3. URL 规则

基础 URL 为 HTTPS 协议、主机和可选固定路径前缀，不接受嵌入凭据、查询参数或 fragment。

```text
目标路径 = 上游路径前缀（去掉末尾分隔斜杠） + 请求路径
目标查询字符串 = 原始请求查询字符串
```

只处理拼接边界，不对路径解码再编码，不排序查询参数，不自动去重 /v1。目标主机始终来自保存的上游配置，不能被请求路径覆盖。

| 基础 URL | 请求路径 | 目标 |
| --- | --- | --- |
| https://a.example.com | /v1/messages?x=1 | https://a.example.com/v1/messages?x=1 |
| https://a.example.com/gateway | /v1/messages | https://a.example.com/gateway/v1/messages |
| https://a.example.com/v1 | /messages | https://a.example.com/v1/messages |
| https://a.example.com/v1 | /v1/messages | https://a.example.com/v1/v1/messages |

最后一行不自动纠正，页面提供示例。实际序列化受 Workers URL / Fetch API 约束。WebSocket 对外使用 WSS，内部向对应 HTTPS 上游发起 Upgrade，共用同一上游配置。

## 4. 鉴权与头处理

入站接受以下二选一：

```http
Authorization: Bearer <转发Key>
```

```http
x-api-key: <转发Key>
```

两者同时存在且值相同可接受，值不同返回 400；格式不合法则拒绝。不从 Cookie、查询参数、请求体或 WebSocket 消息寻找转发凭据。

计算 Key 的 SHA-256 摘要，在未过期配置快照构建的摘要 Set 中匹配，不尝试 ADMIN_KEY 回退认证。每个新请求都在内存检查 Key；仅缓存缺失或过期才读 D1。缓存有效时未知 Key 直接拒绝，不因每个未知 Key 强制刷新数据库。新建 Key 因此也可能需要等待其他实例刷新。

验证后移除入站 Authorization 和 x-api-key，按上游配置写入 Authorization: Bearer 或 x-api-key。保留 Content-Type、Accept、版本头、幂等 Key 等业务头；Host 由目标地址决定，普通逐跳头按协议处理。WebSocket Upgrade 使用专用分支，保留升级和子协议协商所需信息。

移除项目专属会话 Cookie，不主动改写其他业务 Cookie、Origin 或客户端 IP。不承诺头顺序、大小写、压缩表示、分块或 WebSocket 帧边界一致。

## 5. 转发流程

1. 分离管理路径与代理路径。
2. 获取未过期的配置快照：内存命中直接使用，缺失或过期则等待共用的 D1 加载；失败返回 503。
3. 在同一快照中校验转发 Key 并取得全局当前上游；无有效 Key 则拒绝，无上游则返回配置错误。
4. 解密上游 Key，构建 URL 并替换鉴权。
5. 用原方法和请求流回源一次，GET / HEAD 不附带请求体。
6. 使用手动重定向模式，保留上游响应。
7. HTTP / SSE 直接返回流；WebSocket 保留升级连接对象返回。

不读取完整业务请求或响应，不重写 JSON。开始响应后若中断，关闭流或连接，不追加错误 JSON。

### 不透明业务流约束

代理路径不能调用 Request/Response 的 json()、text()、formData() 或 arrayBuffer() 来整包读取业务体；不使用 JSON.parse、JSON.stringify、文本编解码或 SSE 解析器转换业务载荷。请求体直接使用原请求的流，响应体直接使用上游响应流；WebSocket 直接透传升级连接。不得解包、增加外层对象、调整字段层级、增删或重命名字段，不能因不同模型或接口走不同的业务转换分支。

URL、鉴权头和 Upgrade 信息的读取属于必要的代理控制逻辑；管理 API 的 JSON 校验、D1 配置 JSON 的序列化不受此业务体限制。Worker 不主动改变业务载荷，但运行时的 HTTP 编码、压缩与传输分块不承诺在线路字节层面完全相同。

## 6. 数据结构

采用 D1 的单表单行配置，不建用户表、会话表或请求日志表。

| 表 | 字段 | 说明 |
| --- | --- | --- |
| config | id、version、config_json、updated_at | id 固定为 1 且为主键，version 单调递增，迁移创建空配置 |

config_json 结构：

```ts
type Config = {
  activeUpstreamId: string | null;
  upstreams: Array<{
    id: string;
    name: string;
    baseUrl: string;
    authType: "bearer" | "x-api-key";
    keyCiphertext: string;
    keyIv: string;
    keyVersion: number;
  }>;
  accessKeys: Array<{
    id: string;
    name: string;
    keyHash: string;
    keyPrefix: string;
    createdAt: string;
  }>;
};
```

以主键读取一行取得完整配置，不按上游或 Key 数量增加读取行数；实际扫描量以 D1 的 meta.rows_read 为准。version 用于并发修改校验和防止旧加载覆盖新缓存，不为它单独逐请求查询。

管理写入先从 D1 主实例读取最新版本，校验目标存在、当前项不可删除、Key 摘要唯一等约束，再执行 `UPDATE config SET config_json = ?, version = version + 1, updated_at = ? WHERE id = 1 AND version = ?`。影响行数为 0 时返回 409，提示刷新后重试，不覆盖其他并发修改；成功后将本次提交的版本及快照发布到本实例缓存。

转发 Key 使用至少 256 位安全随机熵，建议带 relay_ 前缀。只存摘要，明文仅创建时返回一次。key_prefix 仅用于辨识，不用于认证。

网页登录使用固定有效期的签名 Cookie，建议 1 小时，不存数据库。负载仅包含用途、签发时间、到期时间和随机 nonce，不包含管理密钥或上游 Key。通过 HKDF-SHA-256 从当前 ADMIN_KEY 派生专用签名密钥，使用固定用途标识 `worker-relay/admin-session/v1`；用 HMAC-SHA-256 对编码后的负载签名，固定算法并验证签名、用途、时间及最大有效期。使用 Web Crypto 验签，不接受客户端选择算法。管理密钥须足够随机，不能使用短口令。

Cookie 使用 Secure、HttpOnly、SameSite=Strict，Path=/_relay/；不使用要求 Path=/ 的 __Host- 前缀。每次管理请求按当前 Secret 验签，不查询 D1；Secret 轮换生效后旧签名不再有效。退出仅清除浏览器 Cookie，不承诺已复制令牌立即失效；到期或轮换管理密钥可使其失效。

### 配置缓存规则

- 默认 TTL 为 30 秒，可通过非敏感部署变量 `CONFIG_CACHE_TTL_SECONDS` 调整；设为 0 表示每次读取。
- 模块级缓存保存版本、不可变快照、Key 摘要 Set 和过期时间，缓存中保留上游 Key 密文，回源前解密。
- TTL 从本次 D1 读取发起时计时，不因每次命中延长；若读取完成时已过期，本次等待请求可使用刚读结果，但不能再把它当成新的有效 30 秒缓存。
- 同一实例使用一个正在加载的 Promise 合并并发读取，完成或失败后清除；不定时轮询，无请求就不刷新。
- 正常刷新从主实例读最新配置，失败返回 503，不延长或使用过期快照。
- 管理提交成功后更新本实例缓存；迟到的旧版本读取不得覆盖新版本，等待旧读取的请求优先使用已发布的新版本。
- 管理并发写入也按版本单调发布；旧版本不能覆盖新版本，也不能通过重复发布旧版本延长 TTL。
- 已取得快照的在途请求可继续完成；其他实例无主动失效通知，缓存过期后按需刷新，不承诺全站每 30 秒只读一次。

## 7. 管理 API 草案

统一前缀 /_relay/api。登录只接受管理密钥，其余只接受有效管理会话。所有修改操作含登录均校验同源 Origin。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | /session | 验证管理密钥，创建会话 |
| DELETE | /session | 清除当前浏览器 Cookie 并退出，无服务端会话撤销 |
| GET | /config | 返回代理地址及当前上游 |
| GET / POST | /upstreams | 列表 / 新增上游 |
| PATCH / DELETE | /upstreams/:id | 编辑 / 删除非当前上游 |
| PUT | /active-upstream | 全局选择，null 表示取消 |
| GET / POST | /keys | 元数据列表 / 创建并一次性返回明文 |
| DELETE | /keys/:id | 撤销转发 Key |

上游查询不返回密文或明文 Key；Key 列表不返回摘要或明文。所有管理读写直接访问 D1，写入使用版本条件更新，保证当前上游引用有效且不丢失并发修改，不静默选择其他项。

## 8. 错误与浏览器行为

Worker 自身错误返回 JSON error.code 与 error.message；上游错误保留原状态与内容。

| 状态 | 场景 |
| --- | --- |
| 400 | 参数、URL 或鉴权头冲突 |
| 401 | 管理密钥错误、当前快照中的转发 Key 无效、签名 Cookie 无效或过期 |
| 403 | 管理请求来源校验失败 |
| 404 | 配置或 Key 记录不存在 |
| 409 | 无当前上游、删除当前上游、配置版本冲突 |
| 502 | 回源网络错误 |
| 503 | 无可用缓存且配置读取失败，或管理操作的存储不可用 |
| 500 | 解密失败或内部错误 |

Cloudflare 平台错误可能在 Worker 外产生，不能保证统一结构。

页面与管理 API 同源。代理不自动放宽 CORS、不回答匿名预检，不改写上游 CORS 头，不保证任意跨域网页可调用。第一版不提供浏览器 WebSocket 的查询参数或子协议鉴权方案。

## 管理侧鉴权检测

`POST /_relay/api/test-auth` 需要管理会话及同源请求，接收 baseUrl、可选 id 和 key。复用上游地址校验；只允许对原地址使用已保存的加密密钥。服务端并发发出三个 GET /models 请求（匿名、Bearer、x-api-key），各自 10 秒超时，不跟随重定向；仅检查最多 256 KiB 的模型列表 JSON，不回传密钥或上游响应体。返回两种方式的 HTTP 状态及 available / rejected / unknown，不写 D1、不更新缓存。此管理工具独立于透明转发路径。
