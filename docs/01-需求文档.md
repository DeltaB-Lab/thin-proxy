# thin-proxy 需求文档

版本：V1.7（D1 共享故障状态、30 分钟冷却与手动清除）
日期：2026-10-15

## 1. 目标与使用方式

在 Cloudflare Workers 上部署轻量反向代理。本地只配置固定地址和转发 Key，通过网页管理、切换第三方中转站，无需每次修改本地配置。

项目为单用户自用工具。没有用户注册、用户列表、角色权限或多租户配置。

```text
管理：Secret 中的管理密钥 → 登录网页 → 管理上游、切换上游、创建转发 Key
调用：本地固定 URL + 转发 Key → Worker → Key 指定或默认上游 URL + 上游 Key → 返回响应
```

## 2. 已确认需求

| 项目 | 要求 |
| --- | --- |
| 平台 | Cloudflare Workers |
| 用户模式 | 单用户，不做用户管理 |
| 网页登录 | 使用 Worker Secret 中的管理密钥 |
| 转发鉴权 | 登录网页后单独创建转发 Key |
| 多个转发 Key | 每个 Key 可配置有序上游列表，按顺序选择未冷却项，每次请求仅回源一次；未绑定时跟随默认上游 |
| 上游管理 | 保存多个第三方中转站的 URL、Key 和鉴权方式 |
| 切换方式 | 在网页选择默认上游，或修改单个 Key 的上游绑定 |
| 转发范围 | HTTP、SSE、WebSocket，业务内容透明转发 |
| 配置存储 | D1 保存一份配置，不存请求记录或会话表 |
| 配置缓存 | Worker 实例内存缓存，默认 30 秒；过期按需读取 D1 |
| 网页会话 | 短期签名 Cookie，验证无需查询数据库 |
| 首版边界 | 同一请求每个所选上游最多尝试一次，不转换 API 协议，不在已返回的流中切换 |

不区分客户端名称。所选上游必须支持客户端发送的接口与协议。

## 3. 三类密钥

| 名称 | 来源与存储 | 用途 |
| --- | --- | --- |
| 管理密钥 | 部署者设置，保存于 Worker Secret，建议名为 ADMIN_KEY | 只用于网页登录，不作为转发凭据 |
| 转发 Key | 网页创建，服务端保存摘要及加密副本 | 只用于调用代理，不能登录或修改配置 |
| 上游 Key | 第三方提供，保存于上游配置 | Worker 回源时使用，不承担管理或本地调用认证 |

多个转发 Key 只是可独立撤销的调用凭据，不代表多个用户。管理密钥轮换不影响转发 Key；撤销转发 Key 不影响管理登录。

## 4. 功能范围

### 网页登录

输入管理密钥后进入唯一管理页面，无需用户名。验证成功后签发短期 Cookie，不保存服务端会话记录。退出清除当前浏览器 Cookie，不提供单会话服务端撤销；已复制的 Cookie 在到期或管理密钥轮换前仍可能有效。管理密钥通过部署配置轮换，不通过网页修改 Secret。

### 转发 Key 管理

创建、查看列表、再次查看或复制明文、修改名称及上游列表与顺序、撤销转发 Key。建议允许填写名称，例如“电脑”“服务器”，列表展示名称、辨识前缀、创建时间及上游绑定。

新建 Key 保存加密副本，管理员可再次查看或复制，服务端不明文入库。旧 Key 若只有摘要则无法恢复明文，但调用和路由编辑仍可使用。初次部署不自动把管理密钥作为转发 Key。不做 Key 级配额、权限细分、到期时间或调用统计。

### 上游管理与切换

- 新增、编辑、删除上游，包含名称、基础 URL、上游 Key、鉴权方式。
- 鉴权至少支持 Authorization Bearer 与 x-api-key。
- 全局最多一个默认上游；Key 按指定列表从前往后选择未冷却且未被探测的上游，每次请求仅访问一项，未绑定时跟随默认。未绑定且无默认时返回配置错误；已绑定 Key 不受默认选择影响。
- 切换成功表示配置已提交 D1，处理该修改的实例更新本地缓存；其他实例在缓存过期后读取新配置，默认可能有约 30 秒生效延迟，不承诺全球立即生效。
- 已读到旧配置的请求，以及已建立的 SSE / WebSocket 连接，继续使用原上游。
- 删除默认上游前先切换或取消默认选择；删除被 Key 绑定的上游前先修改绑定、解除绑定或撤销相应 Key。
- 不自动测试上游，不修改本地地址或转发 Key。

### 请求与响应

本项目只做反向代理，不做 API 适配器。代理业务请求体与响应体均作为不透明字节流处理：不解析 JSON、表单、multipart、SSE 事件或 WebSocket 消息；不解包、套壳、增删字段、重命名字段、调整嵌套层级或重新序列化。模型、消息、工具调用、图片及其他内容都不做特殊处理。即使上游协议不兼容，也直接返回其结果，不尝试转换。

此约束针对代理业务流量；为完成转发，Worker 仍需读取请求方法、URL、鉴权头和 Upgrade 信息。管理页面提交的配置 JSON 可以解析和校验。允许修改的范围仅为目标地址及已约定的鉴权字段、项目专属会话 Cookie 和协议所需的传输头处理，不扩展到业务体。

- 保留方法、查询参数、请求体和业务响应，不解析或重写业务内容。
- 按规则替换目标 URL 和鉴权字段；上游路径末尾与请求路径开头重复的完整 /v1 段自动合并，其他路径内容及编码保持不变。
- 其他业务 Header 尽量保留；Host、逐跳头及平台管理的头按运行时处理。
- 每次请求只选择列表中首个未冷却且未被探测的上游并回源一次。网络错误、等待响应头超时、401 / 403 / 408 / 429 和 5xx 使该上游冷却，本次错误直接返回；客户端重试时再选择上游。不自动跟随重定向。
- 冷却默认 1800 秒（30 分钟），可通过 UPSTREAM_COOLDOWN_SECONDS 配置为 1–86400 的整数。到期每个实例仅放行一次探测请求，非故障响应恢复可用，失败开启下一轮冷却。全部冷却或正在探测时返回 503 与 Retry-After。状态保存于 D1 上游配置，其他实例随默认 30 秒配置缓存刷新同步；本实例发现故障立即避让。正常请求不额外查库，故障上报和手动清除产生少量额外读写。
- 首个同版本故障原子推进健康版本并记录截止时间；旧版本上报更新 0 行，静默忽略、不重试、不延长冷却。手动清除始终推进健康版本，即使当前无故障也阻止旧请求写回。D1 故障写入失败保留本机冷却，仅记录内部错误，不替换原上游响应。
- 所有请求体直接流式传递，不缓存、不重放，不设应用级大小上限；受平台与上游大小限制。单次响应头等待默认 30 秒，可通过 UPSTREAM_TIMEOUT_SECONDS 调整为大于 0 且不超过 300 秒。
- 客户端取消不触发冷却；HTTP / SSE 响应已返回或 WebSocket 已升级后不重试，后续流错误不改变健康状态。修改上游 URL、鉴权方式或密钥重置该上游健康状态，改名、排序及 Key 绑定变化不重置。客户端自行重试仍可能重复执行已被上游接受的操作。
- SSE 直接透传流，不整包缓存或重组事件。
- WebSocket 透传握手和消息，不注入心跳、不自动重连、不解析消息。
- WebSocket 鉴权须在握手请求头中完成，不替换消息体内的 Key。
- 浏览器原生 WebSocket 不能任意设置 Authorization；第一版不新增查询参数或子协议鉴权，不能提供支持的鉴权头时不保证兼容。
- 撤销 Key 在各实例刷新配置后阻止后续认证，默认可能延迟约 30 秒，不保证立即中断现有请求和长连接。

“透明”指业务内容透传，不承诺 Header 顺序、大小写、传输分块或底层字节完全一致。连接能力受 Cloudflare、客户端和上游实际限制约束。

## 5. 最小页面

登录页与一个管理页面。管理页面只有固定代理地址及示例、当前上游、上游管理、转发 Key 管理、退出登录。

不做聊天界面、本地常驻程序、客户端配置文件管理、计费、用量统计、对话历史、负载均衡、模型映射、公开注册、通用 TCP / UDP 代理或网页内容重写。

## 6. 非功能要求

管理认证与代理认证分离；转发 Key 必须通过当前未过期配置快照的验证才可回源。日志不记录密钥、请求体、响应体或 WebSocket 消息。上游 Key 需可解密使用，不向页面回显明文。业务响应不主动缓存。

D1 只保存上游配置、转发 Key 摘要、加密副本及有序上游绑定、全局默认选择及必要配置元数据。Worker 内存缓存配置快照，默认有效期 30 秒，命中时不查询 D1；同一实例的并发刷新共享一次读取。缓存过期或冷启动时必须成功读取配置，刷新失败返回错误，不继续使用过期配置。内存不保证常驻或跨实例共享，不能承诺全站每 30 秒只查询一次。

创建新 Key、修改 Key 绑定、修改上游、取消选择同样受缓存生效延迟影响。管理页面读写直接使用 D1，不能以过期的代理缓存覆盖最新配置。

## 7. 验收标准

| 场景 | 预期 |
| --- | --- |
| 管理密钥登录 | 进入唯一管理页面，不需要创建账号 |
| 转发 Key 登录或修改配置 | 拒绝 |
| 管理密钥或网页会话调用代理 | 拒绝，不回源 |
| 创建两个转发 Key | 可分别使用不同上游和鉴权；未绑定时跟随默认上游 |
| 修改 Key 绑定 | 保持原 Key 不变，后续请求按新绑定回源；已建连接不迁移 |
| 删除被绑定上游 | 返回 409，先解除绑定或撤销关联 Key |
| 网页切换 A 到 B | 提交 D1 并更新本实例；其他实例过期刷新后未绑定 Key 使用 B，已绑定 Key 不变；默认约 30 秒延迟，本地配置不变 |
| 创建或撤销一个 Key | 其他实例刷新配置后识别新增或撤销，其他 Key 和管理会话正常 |
| 配置缓存命中 | 在内存验证 Key 并选择上游，不查询 D1 |
| 同实例并发缓存失效 | 共享一次读取，不同时重复加载 |
| 缓存过期且 D1 读取失败 | 返回错误，不用过期配置回源；未过期缓存仍可使用 |
| 网页登录与退出 | 使用签名 Cookie，无会话表；退出清除当前浏览器 Cookie |
| 轮换管理密钥 | 旧管理密钥及旧会话失效，转发 Key 保持有效 |
| 无默认上游 | 已绑定 Key 正常调用，未绑定 Key 返回明确配置错误 |
| 普通转发 | 路径、方法、查询和业务内容正确；上游收到自己的 Key，不收到转发 Key |
| 业务体透明性 | 嵌套 JSON、含特殊空白的 JSON、非 JSON 文本、二进制及 multipart 原样流转，不解包、套壳或改层级；受控上游验证应用层载荷一致 |
| 上游错误或重定向 | 可转移错误按列表继续；其他响应或最后一项 HTTP 错误原样返回；重定向不跟随 |
| 上游顺序 | A → B → C，A 成功不访问 B/C；A 失败访问 B，后续新请求仍从 A 开始 |
| Key 再次查看 | 管理员取得创建时同一明文；无会话或跨域拒绝；旧摘要 Key 明确提示不可恢复 |
| SSE / WebSocket | 流及时到达、消息双向可达，切换不迁移已建连接 |

## 8. 状态

本版替代此前的多用户及每请求直读设计。单用户、凭据分离、Key 有序上游列表或跟随默认上游、D1 + 30 秒实例内存缓存、无会话表为当前方案。初版代码位于项目根目录 `../`，已完成本地运行时测试；按用户要求只做本地开发与测试，未部署 Cloudflare 云端。实际限制和启动方式见项目 README。
