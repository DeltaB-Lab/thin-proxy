| --- | --- |
| 项目名称 | thin-proxy |
| 根目录 | / |
| 构建命令 | npm run check |
| 部署命令 | npx wrangler deploy |
| 预览分支构建 | 关闭 |
| Node.js | 24.3.0，由 .node-version 固定 |

推送到 main 后，Cloudflare 安装锁定依赖，执行类型检查、33 项本地测试及静态资源构建，成功后部署。测试使用临时本地 D1，不访问生产数据库或真实上游。

## 运行配置

- `DB`：绑定专用 thin-proxy D1 数据库，真实 ID 写入 wrangler.jsonc。
- `ADMIN_KEY`、`UPSTREAM_KEY_ENCRYPTION_KEY`：Worker 运行时 Secret，不是构建环境变量。不要提交到 Git。
- `CONFIG_CACHE_TTL_SECONDS`：30。
- `SELF_HOSTS`：本服务的域名列表。

初始化迁移在首次发布前单独执行：`npm run db:remote`。自动构建不运行数据库迁移，避免构建令牌承担不必要的 D1 写入权限及普通提交更改生产数据。以后新增迁移时，先评估兼容性并显式执行迁移，再发布依赖新结构的代码。

生产运行时从 Cloudflare Secret 读取密钥，本地统一在 `.env` 保存管理和加密密钥；普通部署不会上传 `.env`、本地数据库、账号配置或真实上游配置。首次上线后通过管理页面自行添加上游。

## 自定义域名

生产仅通过 `llm-api.drt3b.com` 访问，Cloudflare Worker 自定义域绑定管理 DNS 与证书。`wrangler.jsonc` 固定 `workers_dev: false`、`preview_urls: false` 和自定义域路由，避免后续发布恢复默认域名。main 以外的分支不自动部署。

本地仓库只使用 `.env` 保存 ADMIN_KEY 和 UPSTREAM_KEY_ENCRYPTION_KEY，已由 `.gitignore` 排除，Wrangler 本地开发直接读取它。换电脑时复制该文件即可保留密钥，不再使用 `.dev.vars` 或 `.dev.vars.production`。本地 D1 与云端 D1 仍各自独立；如果需要保留本地配置，还需搬迁 `.wrangler` 状态。`llm-api.drt3b.com` 不能作为本服务的上游地址。

## 平台日志

`wrangler.jsonc` 开启 Workers Observability 与 Workers Logs，`head_sampling_rate` 为 1，`invocation_logs` 和 `persist` 均为 true。main 自动发布后，可在 thin-proxy 的 Observability 页面查询调用日志。日志由 Cloudflare 保存，不写入 D1；应用不增加密钥或业务内容的日志输出。
